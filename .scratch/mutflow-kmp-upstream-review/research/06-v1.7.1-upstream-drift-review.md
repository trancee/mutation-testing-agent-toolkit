# MutFlow 1.7.1 Upstream Drift Review

**Date:** 2026-10-29
**Status:** Review of issue #26. The upstream comparison is documentation-only;
the toolkit pins are current. A local checker fix is implemented and verified
but is not committed or published.

## Trigger

The scheduled [Upstream synchronization run #40890378972](https://github.com/trancee/mutation-testing-agent-toolkit/actions/runs/40890378972)
failed its upstream check and opened [issue #26](https://github.com/trancee/mutation-testing-agent-toolkit/issues/26).
The issue asks whether changes after MutFlow `v1.7.1` contain unreleased API
changes and explicitly says not to pin snapshots.

## Verdict

1. `v1.7.1...master` is ahead by three commits, with no commits behind.
   The comparison changes only `DESIGN.md` and `README.md`; it contains no
   source, build, dependency, or workflow files.
2. The documentation describes existing `MutFlow.underTest` behavior and the
   `ACCUMULATE` verification mode. `VerificationMode.ACCUMULATE` is already
   present in the `MutFlow.kt` source at both `v1.7.1` and `master`; it is not
   an API introduced by these three commits.
3. Maven Central still lists `1.7.1` as the latest stable and release for both
   `mutflow-gradle-plugin` and `mutflow-junit4`. No pin change is warranted.
4. The monitor failed because it treated every non-identical comparison as an
   API-drift error. The fix classifies only complete, documentation-only
   `ahead` comparisons as informational; code/build changes and incomplete or
   diverged comparisons still fail.

## Findings

The GitHub compare API reports `ahead_by: 3`, `behind_by: 0`. Its aggregate
diff is `DESIGN.md` (+37/−15) and `README.md` (+38/−5). The commits are
`3a3fe28a9b32598d64b02335815da3fd37fd89e5`,
`bf0c18714693fa7a9bdb06a34dd5106661f8c596`, and
`20014344b1d2a46314d292c8acff449644fb0283`. The first clarifies the scope
and rationale of `MutFlow.underTest` and updates the design document's
verification-mode description; the latter two make small README wording
edits. The full commit diffs contain no implementation or build changes.

The `ACCUMULATE` mode was added upstream before `v1.7.1`, and the defining
`MutFlow.kt` file is identical between that tag and `master`. The new prose
therefore documents already-published behavior rather than adding an
unreleased API.

Fresh Maven Central metadata confirms `1.7.1` remains both `<latest>` and
`<release>` for the plugin and JUnit 4 adapter. The scheduled job's exit code
is also intentional: the workflow publishes the checker output and creates
or updates the review issue when the checker fails. The failure exposed an
overly broad comparison rule, not a workflow execution problem.

The checker now accepts documentation-only comparisons only when the status
is `ahead`, the file list is nonempty and contains fewer than 300 entries, and
every entry has a recognized documentation suffix. GitHub documents that
compare responses include at most 300 changed files, so lists at that limit
are treated as incomplete and remain review failures. Regression coverage
checks documentation-only changes, mixed documentation/source changes,
missing file details, diverged status, and the 300-file boundary.
